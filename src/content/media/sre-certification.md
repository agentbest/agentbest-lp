## SREにとっての資格の位置づけ

SRE（Site Reliability Engineering）の採用・評価において、資格は「あれば加点になるが、なくても支障はない」領域と「実務の代替として一定の証明力を持つ」領域に分かれる。この区別を理解せずに資格取得に時間を投じると、転職活動や社内評価への効果が限定的になりやすい。

SREはソフトウェアエンジニアリングとインフラ運用の両方に精通し、信頼性・可用性・スケーラビリティを継続的に改善する役割を担う。評価軸が広い分、資格単体が評価に占めるウェイトはフロントエンドや一部のセキュリティ職種よりも低い傾向がある。一方で、特定のクラウドプラットフォームや技術スタックに関する資格は、実務経験が浅い段階での知識担保として機能しやすい。

以下では、SREのキャリアにおいて資格がどのような文脈で評価されるかを構造的に整理し、取得を検討する際の判断軸を示す。

## SREが取得を検討しうる資格の分類

資格は大きく三つのカテゴリに分類できる。「クラウドプラットフォーム系」「Kubernetes・コンテナオーケストレーション系」「ネットワーク・インフラ基礎系」である。それぞれの評価文脈と実務との接続度は異なる。

### クラウドプラットフォーム系

クラウド資格は、SREの文脈では最も証明力が高い部類に入る。特に業務で特定のクラウドを使っていない段階でのスキルの可視化、あるいは異なるクラウドへの移行を伴うポジションへの転職において、採用担当者が参照しやすい指標となる。

代表的なものは以下のとおりである。

| 資格名 | 提供元 | SRE文脈での評価 | 難易度目安 |
|---|---|---|---|
| AWS Certified Solutions Architect – Professional | AWS | 高め（設計・コスト最適化まで問われる） | 高 |
| AWS Certified DevOps Engineer – Professional | AWS | SRE文脈との親和性が高い | 高 |
| Google Cloud Professional DevOps Engineer | Google Cloud | GCP環境のSREに直結 | 高 |
| Google Cloud Professional Cloud Architect | Google Cloud | 設計力の証明として有効 | 高 |
| Microsoft Azure Administrator（AZ-104） | Microsoft | Azure主体の環境では参照されやすい | 中 |
| AWS Certified SysOps Administrator | AWS | 運用寄りのポジションでは有効 | 中 |

Professionalレベルは実務経験なしの合格が難しい設計になっているため、業務経験と試験対策を組み合わせて臨む形が一般的である。AssociateレベルはSRE経験者にとっては比較的取得しやすいが、単独での差別化効果は限定的になりやすい。

### Kubernetes・コンテナオーケストレーション系

Kubernetesを中心としたコンテナ関連資格は、SREポジションにおける評価が近年高まっている。特に「CKA（Certified Kubernetes Administrator）」は実技形式の試験であり、知識ではなく操作能力を問う構造から、採用側の信頼度が高い傾向がある。

| 資格名 | 提供元 | 特徴 |
|---|---|---|
| CKA（Certified Kubernetes Administrator） | CNCF | 実技形式。SREとの親和性が高い |
| CKAD（Certified Kubernetes Application Developer） | CNCF | 開発者寄りだが、SREの知識補完に有効 |
| CKS（Certified Kubernetes Security Specialist） | CNCF | セキュリティ領域との掛け合わせで評価されやすい |

CKAは「Kubernetesを触ったことがある」という表明に客観性を付与する資格として機能する。Helmやネットワークポリシーの理解まで問われるため、実務で扱っている技術範囲を棚卸しする機会にもなる。

### ネットワーク・インフラ基礎系

CCNA（Cisco Certified Network Associate）やLPIC（Linux Professional Institute Certification）は、SREのキャリア初期における基礎力の証明として取得されることが多い。ただし、SREとしての実務経験が一定以上ある段階では、これらが採用の決定打になるケースは少ない。

## 評価されにくい資格・注意すべき取得パターン

次に挙げる資格や取得パターンは、SREのキャリア文脈では評価に繋がりにくい傾向がある。

**ITパスポート・基本情報技術者試験**：知識の入口として有用だが、SREのポジションを志す人材の書類評価においては、経験・ポートフォリオに比べて評価ウェイトが低い。既に実務経験がある場合はアピールポイントとして機能しにくい。

**取得タイミングが実務から乖離している場合**：たとえばAWSをほとんど使っていない環境でAWS資格を複数取得している場合、「資格は持っているが実務経験が伴っていない」と見られやすい。資格と職務経歴書の整合性は採用担当者が無意識に確認するポイントである。

**資格の横展開（同系統を複数取得するケース）**：クラウド3社の同レベル資格を並べることは、特定のプラットフォーム専門性の証明にはなりにくい。深さよりも広さを示す形になりやすく、SREとして特定のスタックに熟達していることの証明にはなりにくい場合がある。

## ケーススタディ：資格取得が有効に機能した転職の型

以下は、資格取得がSREへの転職や評価向上に有効に機能しやすいパターンの典型例である。

**前提：インフラエンジニア3年目、オンプレ中心の環境からクラウドネイティブなSREポジションへの転職を検討**

この状況では、クラウドの実務経験が職務経歴書から読み取れないため、採用企業はスキルの確認手段を持ちにくい。AWSまたはGoogle CloudのProfessionalレベルを取得し、取得過程で学んだアーキテクチャ設計・コスト最適化・障害対応パターンをカバーレターや面接で言語化することで、「実務未経験のクラウド」に関する懸念をある程度緩和しやすい。

さらにCKAを組み合わせると、「コンテナ環境の運用経験がない」という懸念にも対応できる。この場合、資格は「実務の代替証明」ではなく「スキルの翻訳装置」として機能する。

ポイントは、資格を取得した背景・学習過程・実際の業務への接続をセットで語れるかどうかである。資格番号だけが職務経歴書に並ぶ状態では、採用担当者への訴求力は限定的になりやすい。

## 資格よりも評価されやすい実績の形式

SREポジションの採用評価では、以下のような実績・アウトプットが資格よりも高い証明力を持つ傾向がある。

- **インシデント対応の具体的な記録**：障害の検知から根本原因分析（RCA）、再発防止策の実施までの流れを定量・定性で説明できること
- **SLI/SLO設計の経験**：どの指標を選定したか、閾値をどう決めたか、運用後にどう見直したかを語れること
- **IaC（Infrastructure as Code）の実装経験**：TerraformやPulumiを用いた構成管理の設計・運用の実績
- **技術的なアウトプット**：技術ブログ、登壇資料、OSSへの貢献など、外部から参照できる形での知識共有

これらは採用担当者が職務経歴書・ポートフォリオ・面接を通じて確認できる要素であり、資格が果たす「知識の証明」機能を、より文脈に即した形で代替しやすい。

## よくある質問

**Q. SREへの転職で「まず資格を取るべき」と言われましたが、本当ですか？**

実務経験がほぼない段階でクラウドSREを目指すのであれば、資格取得は有効な準備のひとつになりえます。ただし、資格取得を完了してから転職活動を始める必要はなく、学習中の段階で求人を確認し、何が評価軸として求められているかを並行して把握するほうが効率的です。資格が「必須」と明示されているポジションは比較的少なく、経験・思考力・ポテンシャルが主な評価対象になる傾向があります。

**Q. CKAとAWS資格ではどちらを優先すべきですか？**

志望するポジションの技術スタックによります。Kubernetes環境でのSREを志すならCKAの優先度が高く、AWSを主な基盤とする環境を狙うならAWS資格の取得が直接的な証明になります。どちらを先にすべきかは、応募先の求人票やジョブディスクリプションに記載されている技術スタックを確認してから判断するほうが合理的です。

**Q. 資格なしでSREへの転職は難しいですか？**

難しくはありません。特にインフラエンジニア・バックエンドエンジニア・DevOpsエンジニアとしての実務経験があり、SLO設計や自動化・障害対応の経験を具体的に語れる場合、資格の有無が採用の決定要因になるケースは少ない傾向があります。資格は「実務経験がない領域での知識担保」として機能するものであり、経験でカバーできる場合は必須ではありません。

**Q. 資格取得の学習時間はどのくらいを見込めばよいですか？**

クラウドのAssociateレベルであれば実務経験がある前提で数十時間から百時間程度、Professionalレベルは百時間以上を目安とするケースが多いようです。CKAは実技形式のため、演習環境での反復練習が合否に影響しやすく、学習スタイルによって差が出やすい試験です。いずれも個人差が大きいため、模擬試験の正答率を参考に受験タイミングを判断するのが現実的です。

## まとめ

SREにとって資格は「実務経験を可視化する補助手段」であり、それ自体が採用の決定因子になるケースは少ない。クラウドProfessional資格やCKAのように実務との接続度が高いものは証明力を持ちやすいが、実務経験と資格の整合性がとれていない場合は効果が限定的になりやすい。資格取得を検討する際は「何を証明したいか」という目的から逆算し、職務経歴書全体の中での位置づけを設計することが重要である。SRE領域での市場価値を正確に把握したい場合は、現在の経験・スキルセットを踏まえたキャリア相談を活用することも一つの選択肢となる。
